# Backend module map (`functions/` + `cli/`)

This is the **backend** counterpart to the SPA + Rust module maps in
[`CLAUDE.md`](../CLAUDE.md): one row per non-test module under
`functions/` (Cloudflare Pages Functions) and `cli/` (the `terraviz`
publisher CLI). It lives here rather than in CLAUDE.md because the
backend is helper-dense and route-shaped, and sits alongside the
design rationale in the `docs/CATALOG_*` plan docs.

> **Enforced.** `npm run check:doc-coverage` (in the `type-check`
> chain) fails CI if a module under `functions/` or `cli/` is missing
> from this file. Add a row in the same PR; for a module that
> genuinely needs none (throwaway shim), add `// doc-exempt: <reason>`
> to its source. For the deeper *why* behind each subsystem, follow
> the `docs/CATALOG_*` references in CLAUDE.md's _Backend subsystems_.

| `functions/_middleware.ts` | Root middleware: the node's embedding policy (`src/types/node-embedding.ts`) as an appended `Content-Security-Policy: frame-ancestors …` on **every HTML response except the portal's**, whatever the path. Gating on the response rather than the path is the correctness: `_redirects` serves the app's `index.html` for any unmatched path, `/api/nope?embed=1` included, and a path gate let that frame freely (found in review). `?tourEdit=` pages are always locked to `'self'` as a second policy, whatever the setting, because the tour-authoring dock is a publisher write surface on the public document. ## Publisher write API (`functions/api/v1/publish/`)

| File | Responsibility |
|---|---|
| `functions/api/v1/publish/_middleware.ts` | Auth middleware for /api/v1/publish/. First, before it reads anyone's identity, it refuses a request that a page on another origin started, as 403 `cross_origin_request` with a message naming the header and value (`crossOriginRefusal`). A write (any method but GET, HEAD and OPTIONS) needs `Sec-Fetch-Site: same-origin`; `same-site` and `none` are refused, because a `SameSite=Lax` cookie still travels from sibling hosts and `pages.dev` branch previews. Without that header, `Origin` must be the request's own. `Sec-Fetch-Site` comes first because the Vite dev proxy forwards a page's `Origin` to its target. A read another site starts is refused unless it is a top-level visit, since some reads spend YouTube quota or fetch a feed URL. Then it verifies the Access JWT (or the loopback-only dev bypass), refuses a cookie-authenticated write that carries neither header as 403 `origin_required` (`cookieWriteWithoutOrigin`; service tokens are exempt), JIT-provisions the publisher, refuses pending and suspended accounts, and applies the per-node feature gate (`featureForPath`) |
